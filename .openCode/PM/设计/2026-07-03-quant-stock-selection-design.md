# 量化选股工具设计规格

## 1. 背景与目标

本项目从零开始建设一个面向个人研究使用的本地 Web 量化选股工具。工具需要支持 A 股和美股，第一版重点解决技术指标筛选、结果表格查看、个股详情查看、自选股管理和筛选条件模板复用。

第一版目标是完成可重复使用的个人研究流程：选择市场与股票池，配置技术指标条件，基于日线数据执行筛选，在页面表格查看结果，打开个股详情，将股票加入自选股，并保存筛选条件模板供下次复用。

## 2. 已确认需求

- 使用场景：个人研究工具，本地使用，不做多人协作。
- 数据来源：免费公开数据源。
- 第一版选股能力：技术指标筛选。
- 产品形态：本地 Web 应用。
- 数据频率：筛选主流程使用日线；个股详情支持少量分钟走势查看。
- 回测范围：第一版不做回测。
- 结果输出：页面表格查看和自选股列表管理优先；CSV/Excel 导出不作为第一版必需项。
- 用户配置：保存自选股和筛选条件模板。
- 技术栈：FastAPI 后端 + Vue3/Vite 前端。
- 本地存储：文件存储。
- 股票池：A 股全市场 + 美股主流股票。
- 验收标准：完整筛选流程 + 稳定维护个人股票池。

## 3. 总体架构

第一版采用本地 Web 应用架构。

后端使用 FastAPI，负责数据源接入、行情缓存、技术指标计算、筛选执行、自选股和模板文件读写。前端使用 Vue3 + Vite，负责筛选页面、结果表格、自选股管理、筛选模板管理和个股详情展示。存储采用本地文件存储，配置、自选股、筛选模板使用 JSON；行情缓存优先使用 CSV，后续如数据量或性能不足再切换到 Parquet。

运行方式为本机启动后端服务和前端页面，用户通过浏览器访问本地地址使用。市场范围为 A 股全市场和美股主流股票。筛选主流程使用日线数据；分钟数据仅用于少量个股详情查看，不参与第一版批量筛选。

第一版不包含回测、自动交易、多人权限、云同步、实时盯盘和美股全市场覆盖。

## 4. 核心模块与职责

### 4.1 后端模块

- 数据源模块：统一封装 A 股和美股免费数据源，提供股票池、日线行情、少量分钟行情获取能力。
- 缓存模块：按市场、股票代码、频率、日期范围管理本地行情文件，避免每次筛选都重新拉取。
- 指标模块：计算均线、MACD、RSI、布林带、成交量放大、突破和回撤等第一版技术指标。
- 筛选模块：接收筛选条件模板或页面临时条件，对日线股票池批量计算并输出结果。
- 自选股模块：保存自选股分组，支持添加、删除标的，并在结果表格中标记是否已加入自选。
- 模板模块：保存、读取、更新、删除常用技术指标筛选条件。
- 个股详情模块：返回个股基础信息、日线指标和少量分钟走势数据。
- 文件存储模块：集中处理 JSON、CSV 或 Parquet 的读写、校验、备份和异常提示。

### 4.2 前端模块

- 筛选页：配置市场、股票池、技术指标条件，执行筛选。
- 结果表格：展示代码、名称、市场、最新价、涨跌幅、成交量、命中指标、是否自选，支持排序和搜索。
- 自选股页：按分组管理关注股票。
- 模板管理：保存和复用筛选条件。
- 个股详情页：查看日线图、技术指标、少量分钟走势和自选状态。

### 4.3 模块边界

指标计算不直接读写文件。筛选模块只调用数据、缓存和指标服务。前端不直接访问本地文件，所有数据读写都通过后端 API 完成。

## 5. 数据流与文件结构

### 5.1 筛选主流程

1. 前端选择市场、股票池、技术指标条件，或加载已保存模板。
2. 前端调用后端筛选 API。
3. 后端根据市场和股票池读取本地缓存；缺失或过期时调用免费数据源补齐日线数据。
4. 后端对候选股票批量计算技术指标。
5. 后端按条件过滤命中结果，并补充最新价、涨跌幅、成交量、命中原因和自选状态。
6. 前端展示结果表格，用户可搜索、排序、加入自选、打开详情。

### 5.2 个股详情流程

1. 前端请求某个股票详情。
2. 后端读取该股票日线缓存并计算详情指标。
3. 如用户查看分钟走势，后端只对该股票请求少量分钟数据并缓存。
4. 前端展示日线指标、分钟走势和自选状态。

### 5.3 文件结构

```text
data/
  universe/
    cn_stocks.json
    us_popular_stocks.json
  cache/
    daily/
      cn/
      us/
    intraday/
      cn/
      us/
  user/
    watchlists.json
    filter_templates.json
  logs/
    app.log
```

### 5.4 文件格式

- 股票池：JSON，用于维护代码、名称、市场、交易所等元信息。
- 用户配置：JSON，用于手工备份和查看。
- 日线缓存：第一版使用 CSV；后续如数据量或速度不足，再切换到 Parquet。
- 日志：普通文本日志，记录数据拉取失败、缓存更新和筛选异常。

## 6. API 设计

- `GET /api/markets`：返回支持的市场，例如 A 股、美股。
- `GET /api/universe?market=cn|us`：返回股票池列表。
- `POST /api/screen/run`：提交市场、股票池范围、技术指标条件，返回筛选结果。
- `GET /api/stocks/{market}/{symbol}`：返回个股详情、日线指标、自选状态。
- `GET /api/stocks/{market}/{symbol}/intraday`：返回少量分钟走势数据。
- `GET /api/watchlists`：读取自选股分组。
- `POST /api/watchlists/items`：添加自选股。
- `DELETE /api/watchlists/items/{id}`：删除自选股。
- `GET /api/filter-templates`：读取筛选模板。
- `POST /api/filter-templates`：保存筛选模板。
- `PUT /api/filter-templates/{id}`：更新筛选模板。
- `DELETE /api/filter-templates/{id}`：删除筛选模板。

## 7. 前端页面设计

- 筛选页：左侧配置市场、股票池、指标条件；右侧展示结果表格。
- 个股详情页：展示基础信息、日线走势和指标、分钟走势、自选操作。
- 自选股页：展示分组、自选股票列表、移除和跳转详情。
- 模板管理入口：在筛选页中保存当前条件、加载模板、更新模板、删除模板。
- 状态反馈：筛选执行中显示加载状态；数据源失败、缓存过期、无结果时给出明确提示。

技术指标条件第一版采用结构化表单，不做自由表达式。条件形态包括指标、周期、比较关系、阈值和是否启用。

## 8. 错误处理

- 数据源失败：返回明确错误码和提示，例如“数据源不可用，请稍后重试或使用已有缓存”。
- 缓存缺失：允许后端自动拉取；拉取失败时提示缺失的市场、代码和日期范围。
- 指标计算失败：单只股票失败不应中断全部筛选，应记录失败原因并在结果中汇总失败数量。
- 文件读写失败：提示具体配置文件或缓存文件路径，避免静默失败。
- 空结果：前端提示“无匹配股票”，并建议放宽条件。
- 分钟数据失败：不影响日线详情和筛选主流程。

## 9. 测试策略

- 后端单元测试：指标计算、筛选条件判断、文件读写、自选股和模板 CRUD。
- 后端接口测试：筛选 API、个股详情 API、自选股 API、模板 API。
- 前端组件测试或基础页面测试：筛选条件表单、结果表格、自选股操作、模板加载保存。
- 集成验收：用小规模样例股票池完成一次“拉取或缓存数据 -> 执行技术筛选 -> 展示结果 -> 加入自选 -> 保存模板 -> 复用模板”的完整流程。

## 10. 第一版验收标准

- 能选择 A 股或美股主流股票池。
- 能配置至少 3 类技术指标条件，例如均线、MACD、RSI。
- 能执行日线筛选并展示结果表格。
- 能打开个股详情，并查看日线指标与少量分钟走势。
- 能保存、读取、更新、删除筛选模板。
- 能添加、删除、分组管理自选股。
- 数据和用户配置以本地文件形式保存。
- 第一版不要求回测、自动交易、实时行情和美股全市场覆盖。

## 11. 后续非第一版范围

- 策略级回测。
- 自动交易或半自动交易。
- 实时行情盯盘。
- 多人权限和云同步。
- 美股全市场覆盖。
- CSV/Excel 导出。
- 自由表达式策略编辑器。
